# ドメインモデルと初期設計判断

この文書は初期提案です。ユーザー要求の未完部分を確定要件と見なさず、以下の解釈を明示します。

## 正本と時間

各ブランチのgraph.jsonはそのブランチのスナップショットです。default branchのNode集合を
リポジトリの現在の仕様とします。時刻文字列を必須にせず、Git履歴を時間軸とします。
正本Nodeの状態は `current` と `past` の二つだけです。

`null` は仕様のない起点を表す特別なNodeです。常にcurrent、空文字・空グループで固定します。
独立した仕様の追加はnullから始められます。nullを通常Nodeと混在した変更元にはできません。
削除は「この機能は提供しない」という自然言語の新Nodeで表します。nullへ戻る辺は許しません。

## Intentと候補

Intentは理由、唯一のintent-group、空でないbefore集合とafter集合を持つ有向ハイパーエッジです。
単純な辺の集合に展開しても、同じIntentによる原子的な変更というまとまりを保持します。
IssueとPRはそれぞれnullableな一つの番号です。配列にせず最大一件をデータ構造で表します。
同じIssueやPRを別Intentに割り当てることはできません。PRがあるならIssueも必要です。

Issue未対応が「予想」です。Issueあり・適用前は「計画」です。明示的なapplyにより「適用済み」にします。
適用済みIntentにはIssueが必要です。PRを介さない運用を表すためモデル上PRは任意ですが、
PR用CIでは当該PRとの対応を要求します。

予想の変更先をcurrentにすると正本が曖昧になるため、適用前は `proposals` に置きます。
候補はまだNodeではありません。applyで候補をcurrent Nodeに移し、変更元をpastにします。
予想は現在のNodeを変更せず、競合する複数の予想も保存できます。
変更元がpastになった計画は保存・表示できますが、再検討するまで適用できません。
候補から候補への連鎖予想は初期実装では対象外です。

Node本文・所属・適用済みIntentは不変です。訂正も新Intentで記録します。
通常Nodeの生成元は一つ、適用済みの後続Intentも最大一つです。
複数の新Nodeへの分割は一つのIntentのafterに列挙します。

## グループ

spec-groupはリポジトリ内のIDです。通常のSpecは一つ以上に所属します。
intent-groupはリポジトリ非依存の名前空間と版を持ちます（例 `spec-graph:correctness@1`）。
計測方法、エビデンス方式、Issue/PRの必須見出しを定義します。
再現性のためグラフに定義を固定して保存し、既存定義を変更する場合は別ID／版を追加します。
中央レジストリ・他リポジトリとの定義同一性検証は未実装です。

## 保存と更新

専用形式はUTF-8 JSON、パスは `.spec-graph/graph.json` です。単一ファイルを一度に置換し、
半分だけ適用された状態を避けます。同一ファイルへの同時書き込みは対応しません。
別ブランチの競合はGitで解消した後、差分検証をやり直します。

Visualizerは127.0.0.1だけで動作し、認証はローカルのghに委ねます。
ブラウザへの出力はtextContentを使い、仕様やIssue由来のHTMLを実行しません。
永続キャッシュはgraph、blob SHA、ETag、リンク済みIssue/PR状態のみです。
アクセス時に条件付きGETで変更を確認し、304では保存データを再利用します。
Issue/PR状態はグラフが不変でも確認します。全リポジトリの走査やcloneは行いません。
オフライン時は更新失敗を表示し、以前のキャッシュは破壊しません。

## 対象外・未確定

- 大規模グラフの性能保証、配置の永続化、複数リポジトリの統合表示。
- 予想候補からさらに派生する計画、棄却状態や実日時の独立管理。
- 計測結果の真偽判定、自動テスト実行、エビデンス内容の意味的検証。
- GitHub Enterpriseのホスト指定、etag以外のイベント駆動更新。
- intent-groupの共有レジストリ、署名、アップグレード方式。

これらは実装済み機能ではありません。表示はCytoscape.jsとDagreによる有向グラフです。
詳細は [Visualizer](visualizer.md) を参照してください。
